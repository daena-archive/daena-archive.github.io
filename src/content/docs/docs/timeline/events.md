Timeline contributes Event, Encounter, and Era records alongside Calendars. Add participants and locations through shared relationships so the same records remain navigable from Lore and Maps — an encounter's people are the same entities you edit in Lore. (Participants and locations belong to encounters; plain events carry dates and era links.)

Use Eras for named periods and Events for moments, turning points, or spans. Encounters cover meetings and interactions between people at a place and time. Keep project-change history in Snapshots rather than mixing it with fictional chronology: world history belongs in Timeline, project history belongs in Snapshots.

## Working with events

1. **Create from the current tab.** New in Timeline defaults to the active tab's template, so open the Events tab before creating an event or encounter.
2. **Date it simply.** Give the event a date at whatever precision you actually know. Daena does not invent missing time detail.
3. **Attach context.** Link participants, places, and related records. Date, era, and participant relationships survive renames and type changes on either side.
4. **Check the chronology.** The chronology view refreshes after create, archive, restore, or type change — if your event is missing, check filters and type chips (which show schema names, not raw IDs) before assuming it failed to save.

Archiving is available from both the collection and the detail view, and is reversible from Project Center → Archive.
